`run-all-phases.sh` קורא את הקובץ הזה, שולף את הבלוקים שבין הסימנים
`<!-- PHASE_PROMPT -->` … `<!-- END_PHASE_PROMPT -->` ו-`<!-- REPAIR_PROMPT -->` …
`<!-- END_REPAIR_PROMPT -->`, מחליף בהם את ה-placeholders, ומעביר את התוצאה
ל-`claude -p`. אפשר לערוך כאן חופשי — הסקריפט לא צריך שינוי.

Placeholders שמוחלפים אוטומטית:

| Placeholder | מוחלף ב- |
|---|---|
| `__PHASE__` | מספר השלב (2–9) |
| `__BRANCH__` | שם ה-branch של השלב |
| `__GATE_LOG__` | נתיב מלא ללוג הכישלון של שער האיכות (בפרומט התיקון בלבד) |

הטקסט בין הסימנים הוא בדיוק מה שהסוכן מקבל — שום דבר מהמסמך הזה מחוץ לבלוקים
לא נשלח אליו.

כללי איכות — הסקריפט שמריץ אותך יבדוק את אלה בעצמו אחרי שתסיים, ואם הם לא
עוברים כל הריצה נעצרת. אל תדווח על סיום לפני שהרצת אותם בעצמך וראית ירוק:

- `npm run lint`, `npm run typecheck`, `npm run build` — עוברים.
- `npm run db:reset` עובר נקי, ו-`npm run db:test` (pgTAP) עובר.
- לכל טבלה חדשה יש מדיניות RLS **ולפחות טענה אחת** ב-supabase/tests/rls_test.sql
  שמוכיחה שמשתמש אחד לא רואה או משנה נתונים של אחר.
- אם הסכימה השתנתה: `npm run db:types` הורץ מחדש והטיפוסים המעודכנים מקומטים.
- כל נתיב כתיבה בשרת מוודא קלט עם Zod. אין `any` בלי הערה שמסבירה למה.
- RTL: רק utilities לוגיים (`ms-`/`me-`/`ps-`/`pe-`/`start-`/`end-`/`text-start`/
  `text-end`). אין `ml-`/`mr-`/`pl-`/`pr-`/`left-`/`right-`/`text-left`/
  `text-right` בקוד חדש. תעבור על ה-diff שלך ותוודא את זה לפני סיום.
- אין סודות בקוד; `.env.example` מעודכן אם נוסף משתנה סביבה.
- אם הרצת תהליך ארוך (`next dev`, `supabase start`) — תסגור אותו לפני שאתה מסיים.
