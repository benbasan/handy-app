## 1. מה זה Handy, בשלושה משפטים

מרקטפלייס בעברית (RTL) שמחבר לקוחות בישראל עם בעלי מקצוע מאומתים בסביבתם: אינסטלציה, חשמל, מיזוג ועוד, עשרה תחומים בסך הכול. הלקוח מפרסם קריאה בחינם, מקבל הצעות מחיר אמיתיות תוך דקות, בוחר אחת, ומשלם ישירות לבעל המקצוע. בעל מקצוע שנבחר מקבל שעתיים לאשר; האישור גובה ממנו **35 ₪ קבועים, פעם אחת**, ובלי החזר, והוא מה שמשבץ את העבודה.

הבטחת הליבה: **שקיפות מחיר.** המחיר יכול להשתנות רק דרך בקשת עדכון עם תמונה מהשטח, שהלקוח מאשר. זה נאכף במסד הנתונים ולא רק במסך.

## 3. הסטאק בפועל (גרסאות מ-`package.json`)

- **Next.js 16.3.4** (App Router), **React 19.2.8**, TypeScript strict. זו **לא** ה-Next שבנתוני האימון: `middleware.ts` נקרא כאן `proxy.ts`, ה-prop של `error.tsx` הוא `retry` ולא `reset`, ו-`PageProps<"/route">`/`RouteContext` מגיעים מ-`next typegen`. לפני כתיבת קוד Next, לקרוא את `node_modules/next/dist/docs/`.
- **Supabase**: Postgres + RLS, Auth בטלפון, Storage, Realtime, pg_cron, pg_net. `@supabase/ssr` 0.12, `supabase-js` 2.115. ה-CLI הוא devDependency (`supabase@2.116.0`) ומורץ ב-`npx supabase`.
- **Tailwind v4** בלי קובץ config. הטוקנים ב-`@theme` בתוך `app/globals.css`, והמחלקות בעלות השם ב-`components/ui/primitives.tsx`.
- **Zod 4** בכל נתיב כתיבה, ב-`lib/validation/`.
- **@react-pdf/renderer** לקבלות, עם פונטי Heebo ב-`assets/fonts/`.
- **web-push** להתראות דפדפן, **qrcode** לקוד QR בצד השרת.
- בדיקות: **Vitest 3.2.7**, **Playwright 1.63** עם axe, **pgTAP**.
- husky + lint-staged: prettier ו-eslint רצים על כל commit.

## 6. איך עובדים עם הריפו — פקודות ותהליך

### סביבה מקומית

**Node לא נמצא ב-PATH של ה-Bash tool.** בלי זה כל `npx` נכשל בשקט, וגם hook ה-pre-commit של husky נכשל:

```bash
export PATH="$HOME/.nvm/versions/node/v22.16.0/bin:/usr/local/bin:$PATH"
```

Docker Desktop צריך לרוץ בשביל `supabase start`. `gh` **לא מותקן**, ו-`npx vercel ls` עובד.

### פקודות

| פקודה | מה היא עושה |
|---|---|
| `npm run db:start` / `db:stop` | Supabase מקומי |
| `npm run db:reset` | מיגרציות + seed מאפס |
| `npm run db:test` | pgTAP. **רק על DB טרי** — אחרי E2E הנתונים מלוכלכים והבדיקות נכשלות |

| `npm run perf:postgis` | בדיקת עומס לפיד. **חובה בכל שינוי מדיניות על `jobs`** |

1. `npm run db:reset`
2. `npm run db:test`

### תהליך git ודיפלוי (כפי שנעבד בפועל)

1. ענף לכל שלב: `phase-NN-short-name`. תיעוד בלבד: `docs/...`.
2. commits קטנים ב-Conventional Commits, שמסתיימים ב-`Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
3. **אם יש מיגרציה:** `npx supabase db push --yes` **לפני** המיזוג. ה-CI לא מריץ מיגרציות, ו-Vercel יפרוס קוד שמצפה לסכימה שלא קיימת.
4. `git checkout main && git pull --ff-only && git merge --no-ff <branch> && git push origin main`.
5. בדיקה ב-`npx vercel ls` שהדיפלוי במצב Ready. **לא** להריץ `vercel --prod` בנוסף.
6. לעולם לא force-push ל-main.

### מלכודות שכבר עלו זמן

- **`e2e/.auth` ישן אחרי `db:reset`** שולח כל עמוד למסך ההתחברות, ונראה בדיוק כמו רגרסיה. הפתרון: `rm -rf e2e/.auth`.
- **pgTAP על DB שה-E2E כבר שינה** נכשל בלי קשר לקוד.
- **הודעות "The destination stream closed early"** בלוג ה-WebServer של Playwright הן ניווטים שנקטעו, לא כישלון.
- **בטלפון יש שני כפתורי "פרסם קריאה"** (הטופס ופס הפרסום), ולכן ב-Playwright צריך `.first()`.
- **טריגר BEFORE רץ לפני RLS.** טריגר שאוכף כלל צריך לזוז הצידה עבור קורא ש-RLS עומד לדחות, אחרת הוא מחזיר שגיאה לא נכונה (23514 במקום 42501).
- **פונקציית definer בתוך מדיניות RLS** לא עוברת inline, והכפילה את זמן הפיד (585ms). המדיניות על `jobs` כותבת את הכלל כביטויים, ו-pgTAP מוודא שהיא שקולה ל-`pro_reaches_job()`.
- **INSERT ב-pgTAP עם `id` מפורש** נכשל ב-42501, כי אין grant על `id`. מכניסים כ-postgres עם claims מוגדרים.
- **כללי React Compiler ב-lint:** אסור `Date.now()` בזמן render, ואסור לקרוא refs בזמן render.
- **`tests/designTokens.test.ts`** נכשל על `text-lg font-bold text-ink` כתוב ידנית. משתמשים ב-`SECTION_TITLE`, `CARD_BASE` וכו'.
- **`tests/copyPromises.test.ts`** נכשל על הבטחה בעברית בלי קוד מאחוריה, למשל "SMS" או "הזמנה חוזרת" מחוץ לקבצים המותרים.

### משתני סביבה

הרשימה המלאה ב-`.env.example`, והמשמעות של כל אחד ב-`CLAUDE.md` סעיף 9.

- **Supabase:** `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. השלישי לא נקרא בשום מקום בקוד, וזה מכוון.
- **כתובת האתר:** `NEXT_PUBLIC_SITE_URL`.
- **מפות:** `ALLOW_NO_MAPS_KEY=1` חובה בכל סביבה פרוסה, כי אין מפתח Google. `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` ו-`GOOGLE_MAPS_SERVER_API_KEY` ריקים בכוונה.
- **כניסה:**
  - `AUTH_BYPASS_OTP` ו-`AUTH_BYPASS_PASSWORD`: כל מספר נכנס עם קוד קבוע.
  - `NEXT_PUBLIC_DEMO_LOGINS`: כפתורי דמו בדף הבית. זה משתנה build-time, ושינוי שלו דורש דיפלוי.

  - `NOTIFICATIONS_DISPATCH_SECRET`
  - `NOTIFICATIONS_ALLOW_PAID` (כבוי)
- **שונות:** `DATABASE_URL`, `SUPABASE_AUTH_SMS_TWILIO_AUTH_TOKEN`.

**לא אומת במסמך הזה:** אילו מהמשתנים מוגדרים בפועל ב-Vercel, ובמיוחד מפתחות VAPID והסודות ב-Vault שה-push צריך. לפני שמניחים שה-push עובד בפרודקשן, צריך לבדוק.

### מה עוד פתוח בסביבה (מסוכם מ-`CLAUDE.md` סעיף 9)

- **כל אחד יכול להיכנס כמעט כמו כל אחד.** `AUTH_BYPASS_OTP` פעיל, ו-`123456` עובד על משתמשי ה-seed גם בענן, כולל האדמין `972500000005`. זה סיכון מקובל **לדמו פרטי בלבד**, והוא חייב להיסגר לפני המשתמש האמיתי הראשון.
- **אין SMS אמיתי.** Twilio עולה $0.2575 להודעה לישראל; ספק ישראלי הוא התשובה הסבירה, והחיבור הוא Supabase Send SMS Hook.

- **הטקסטים המשפטיים הם טיוטה** (`DRAFT_NOTICE`), ומחכים לעורך דין.
- **אין גיבויים**, ובמיוחד אין גיבוי ל-Storage (ארבעה buckets), שאף תוכנית של Supabase לא מכסה.
- **אין ספק ניטור.** השגיאות נכתבות כ-JSON ל-stderr ו-Vercel שומר אותן.
- **`site_url` בענן מצביע על `127.0.0.1:3000`** (תוצאה של `config push`). זה לא שובר כניסה בטלפון.
- **AI בפרסום קריאה (תמונה ← תחום + תיאור):** נדחה על ידי בעל הפרויקט, ונשאר פתוח.
